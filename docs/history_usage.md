# 历史记录持久化与历史页面

## 安装

本补丁基于已安装的多轮问答与decision_alignment页面；不改变异常阈值配置，也不覆盖demo_threshold模块。

```bash
python install_ecg_history.py --apply
python -m unittest tests.test_history
```

在原服务终端Ctrl+C后重新启动：

```bash
python -m streamlit run app_ecg.py --server.address 127.0.0.1 --server.port 8505 --browser.gatherUsageStats false
```

用于问答的API Key仍需在启动服务的终端提前设置。打开历史、查看波形/证据/对齐、导出均不需要网关，也不重新加载GPU模型。新建分析才会加载模型。

## 使用

- 侧栏“新建分析”：选择样本，点击“本地分析并保存”。更改输入的样本索引不会删除或暗中更换当前已打开分析。
- 侧栏“历史记录”：每页50条，显示样本、时间、分析ID、耗时、提问数量。选择一条并点击“打开历史分析”。
- 当前分析可选择其不同对话；“新建对话”保留旧对话，不做删除。
- 每个对话最多20轮，模型继续使用最近最多3轮成功问答作为背景。失败轮次保存但不加入模型记忆。
- 每轮提问先写入待完成状态，再调用网关。完成或失败立即写入；迟到结果不能覆盖已经结束等待的轮次。
- 地址栏保留analysis和conversation标识。刷新同一地址恢复同一记录；新打开基础地址时从历史页选择。

## 保存在哪里

项目目录local_history/history.sqlite3。SQLite同一次事务保存结构化分析和压缩NPZ数组BLOB，避免“数据库已存但数组文件没落盘”的半条记录。

保存：原始裁剪输入、重构、sigma、error_map、RR明细、模型与阈值来源；对话问题、原始回答、失败状态、证据、知识、调用轨迹和白名单配置。NPZ恢复allow_pickle=False，不用pickle。数组校验摘要和输入哈希在打开时检查。

旧分析使用当时冻结的模型和阈值数据；后来改test.npy、checkpoint或阈值文件不会重算旧分析。继续问答读取旧数值，但使用当前工具代码/知识库/LLM，新一轮是新执行结果，不声称旧代码环境完全复现。

这是单用户本地数据库，不是多人登录权限系统。Linux上同一数据库限制一个页面服务进程，避免多个服务相互恢复对方的待完成任务。另起8506也不能同时使用同一数据库；请先停止旧服务。

数据库随保存量增长，暂不提供自动删除。内存模型分析缓存完成后释放，不再依靠最多32条内存结果保存历史。

## 中断与恢复

服务进程退出后，下一次启动将上一进程未完成轮次标为REQUEST_INTERRUPTED。不会重发LLM请求，不会补写虚构答案。刷新时若原进程仍在执行，页面显示待完成，可以再次刷新查看。

“结束本地等待”只结束本地轮次，不能保证取消已经发出的网关请求；之后到达的响应不会覆盖中断结果。后续需手动再次提问。

## 备份

```bash
python -m evaluation.history_status
python -m evaluation.history_status --backup
```

使用SQLite备份API生成一致数据库副本到local_history/backups。备份包含ECG与问答内容，不应提交到公开代码仓库。恢复时先停止服务，保留现有数据库副本，再用备份替换history.sqlite3后启动。

## 验收

1. 样本0本地分析保存，完成一轮RR问答。
2. 分析样本1，在历史页重新打开样本0；波形与RR须对应样本0。
3. 刷新页面，问答与分析ID不变。
4. 停止服务并重新启动，从历史页打开样本0，继续追问“其中最长的是哪个？”；需能重新查询保存的RR。
5. 当前分析新建第二个对话，再选回第一个，原问答保留。
6. 导出当前对话，核对分析ID、问题顺序、证据和状态。
7. 查看history_status确认分析和轮数。

安装前已经从内存消失的记录无法自动找回。旧JSON/Markdown没有完整数组，当前没有自动导入功能。本次持久化从新页面保存的记录开始。

## 验证范围

离线测试覆盖重启恢复、数组一致、恢复后工具查询、ID隔离、不可覆盖、双提交、超时/中断记录、晚到结果、历史上下文、备份和配置白名单。当前工具环境缺少Streamlit，未执行浏览器交互或真实网关验收；按上面的步骤在用户环境验证。
